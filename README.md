# Guild Master

เกมบริหารกิลด์นักผจญภัยพิกเซลโทน cozy anime สำหรับเว็บ คุณคือหัวหน้ากิลด์ในหมู่บ้านเล็ก ๆ ไม่ต้องจ้างคนหรือส่งทีมเอง นักผจญภัยเดินทางมาลงทะเบียน เช่าห้องในเมือง เลือกงานจากกระดานคำร้องและจับกลุ่มกันเอง หน้าที่ของคุณคือดูแลกิลด์และเมืองให้ทุกคนทำงานได้ดี อยากอยู่ต่อ และพากิลด์จากระดับ F ไปถึงชายแดนตะวันออก

## ระบบหลัก

- **กระดานคำร้อง** ชาวบ้านเดินมาส่งคำร้อง นักผจญภัยหยิบงานเอง คุณตั้งค่าตอบแทน (ใจดี มาตรฐาน ประหยัด) เพิ่มค่าหัว หรือระดมพล กระดานบอกเหตุผลเมื่องานไหนไม่มีใครรับ
- **นักผจญภัยอยู่ในเมือง** มาลงทะเบียนเองตามชื่อเสียง จำนวนถูกจำกัดด้วยที่พักและระดับเมือง (15 · 20 · 25 · 40 · 60 คน) ราว 1 ใน 4 เป็นขาประจำที่มีชื่อ
- **สภาพ 5 ด้าน** บาดแผล ความเหนื่อย อารมณ์ อุปกรณ์ เสบียง รวมเป็นประสิทธิภาพ 60–120% มีแถบประสิทธิภาพ จุดคอขวดเป็นเงิน และสรุปรายวัน
- **กิลด์เป็นบ้าน** บาร์ โต๊ะอาหาร โต๊ะประเมินราคา และพนักงาน 6 ตำแหน่งที่ทำงานให้เห็นในฉาก
- **เมืองมีชีวิต** ชาวเมืองเดินตามกิจวัตร กลางวันกลางคืน ความพึงพอใจ คนย้ายเข้าออก และเมือง 5 ระดับที่เห็นบนแผนที่
- **โลกเรียลไทม์** ล่ามอน ภารกิจหลายรูปแบบ (คุ้มกัน ป้องกันไร่ เก็บของ ช่วยเหลือ) บอสหลายเฟส มอนบุกหมู่บ้าน และโหมดหัวหน้ากิลด์ออกไปสู้เอง (⚔)
- **การเติบโตของนักผจญภัย** แรงค์ F–B สอบเป็นรอบที่สนามสอบ อาชีพ 3 ขั้น
- **การค้า** รับซื้อชิ้นส่วน โรงแปรรูป คาราวาน สมบัติ ตู้โชว์ และโรงประมูล
- **เทศกาล** ประลองยุทธ เก็บเกี่ยว โคมลอย โดยหัวหน้ากิลด์ตั้งรางวัลเอง
- **อีกนิดเดียว** เป้าหมายใกล้ตัวที่มุมจอ เป้าหมายวันนี้ หีบรางวัลลุ้นความหายาก สมุดภาพมอน ชุดสมบัติ และนโยบายกิลด์ 1 ใน 3 ทุกครั้งที่เลื่อนระดับ
- **เนื้อเรื่อง 2 บท** บทที่ 1 ป่าหมอกจันทร์และหัวใจป่า (กิลด์ F → B ราว 1 ชั่วโมงเกม) บทที่ 2 ชายแดนตะวันออกจนถึงราชันมังกรเพลิง (ราว 3 ชั่วโมงเกม)

## เล่นจาก source

```bash
npm ci
npm start
```

เปิด `http://localhost:5173` ใช้ Node.js 20 ขึ้นไป ใช้ Phaser 3.90.0 ที่ติดตั้งไว้ในโครงการ ไม่โหลดจาก CDN ระหว่างเล่น ใช้ WebGL เมื่อเปิดได้ และใช้ตัววาด Canvas ของ Phaser เมื่อ WebGL เปิดไม่ได้ ไฟล์ Android ที่เปิดผ่าน content:// ใช้ตัววาด Canvas โดยตรง

## การควบคุม

วางกระดานคำร้องในกิลด์ แล้วนักผจญภัยจะเลือกงานและจับกลุ่มกันเอง เปิด **คำร้อง** ที่แถบล่างเพื่อดูงานที่ยังไม่มีคนรับและเหตุผล ปรับค่าตอบแทนหรือเพิ่มค่าหัวเพื่อดึงคนเก่งไปทำงานที่อยากให้เสร็จ ระหว่างนั้นพัฒนาเมือง (โรงเตี๊ยม บ้าน ร้านค้า คลินิก) ให้คนมาอยู่มากขึ้นและทำงานได้ดี แตะทีมบนแผนที่เพื่อดูการต่อสู้สด รายละเอียดทุกระบบอยู่ใน [คู่มือผู้เล่น](docs/MANUAL-TH.md)

ลากฉากเพื่อเลื่อน ใช้ +/−, ล้อเมาส์ หรือสองนิ้วเพื่อซูม เมนู → ห้องและต่อเติม เลือกขนาดและชนิดห้อง แล้วแตะพื้นเพื่อสร้าง กดพื้นว่างในห้องเพื่อย้าย/หมุน/ปรับขนาด กดของเพื่ออัปเกรด/ย้าย/หมุน กดคนเพื่อดูรายละเอียด `Space` หยุดเวลา, `1`/`2`/`4` เปลี่ยนความเร็ว, `R` หมุนขณะวาง, `Esc` ปิดเมนูหรือยกเลิกการวาง

เมนู “กิลด์” → เซฟ / ตั้งค่า: บันทึก ส่งออก/นำเข้าเซฟ เสียง และเริ่มเกมใหม่ เกมบันทึกเองอัตโนมัติ เซฟอยู่ในเบราว์เซอร์นี้ ไม่มี cloud save ควรส่งออกไฟล์เซฟก่อนล้างข้อมูลหรือย้ายเครื่อง

## ตรวจและสร้างไฟล์เว็บ

```bash
npm test
npm run build
npm run export
```

`build` เตรียมเว็บหลายไฟล์ใน `dist/`; `export` สร้างไฟล์เดี่ยว `play.html` ใหม่จาก source ปัจจุบัน เมื่อแก้ source ต้องรัน export ก่อนส่งไฟล์เดี่ยวให้ผู้เล่น

ชุดตรวจ engine 60 รายการ รวมบอทที่เล่นทั้งเกมเองตั้งแต่ต้นจนปราบมังกร 5 seed และบอทค่าตอบแทนแบบใจดีและประหยัด (`node tests/pacing.mjs` พิมพ์ตารางจังหวะเกมเต็มของค่าตอบแทน 3 แบบ × 5 seed ดูผลล่าสุดใน [docs/PACING-TH.md](docs/PACING-TH.md)) มี browser smoke test เสริม:

```bash
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs BROWSER_EXECUTABLE=/path/to/chromium node tests/ui-smoke.mjs
node tests/rooms-smoke.mjs
node tests/boot-smoke.mjs
node tests/standalone-compat.mjs
```

ค่าเริ่มต้นของ browser smoke เป็นพาธ runtime ของสภาพแวดล้อมผู้พัฒนา หากรันที่อื่นให้ระบุสองตัวแปรข้างต้น ตรวจการจัดทีม เหตุการณ์ รางวัล คราฟต์ อัปเกรด ย้ายของ และเซฟ/โหลด ส่วน rooms-smoke ตรวจไฟล์ส่งจริง การสร้างห้อง หมุน/ย้ายพร้อมของ ต่อเติมและล็อกตามกิลด์ มือถือ 390×844 เซฟ/โหลด และเปิด offline

การตรวจ boot-smoke เปิดไฟล์ส่งจริงโดยปิด WebGL และจำลอง GPU context หายกลางเกม ตรวจว่าฉากกลับมา วางห้อง ซูม และบันทึก/โหลดได้ โดยรักษาความคืบหน้า ใช้ Chromium และ viewport มือถือจำลอง ยังไม่ได้ทดสอบ Samsung Internet บนอุปกรณ์จริง

`standalone-compat` ตรวจโครงสร้างสคริปต์และเปิดไฟล์ R7 จริงโดยไม่มีตัวโหลด Blob/DecompressionStream ตรวจพิกเซลพื้นว่างและถนน รวมพื้นที่หญ้าและหลังคาบ้านเพื่อปฏิเสธฉากสีเรียบที่มีแต่ของ ทดสอบ Canvas/WebGL วางห้อง เซฟ/โหลด viewport 390×844 และจำลอง Canvas เปิดไม่ได้เพื่อตรวจข้อความผิดพลาด

## ขอบเขตปัจจุบัน

เนื้อเรื่องเล่นได้ถึงกิลด์ระดับ B และราชันมังกรเพลิง บอทที่เล่นเองใช้เวลาเกมราว 160–210 นาทีที่ความเร็ว ×1 (ตัวเลขจากการจำลอง ไม่ใช่เวลาของผู้เล่นจริง) แรงค์ A–S ยังไม่เปิด ยังต้องปรับสมดุลจากการเล่นจริง ความลื่นบนมือถือวัดจาก Chromium จำลองเท่านั้น ยังไม่ได้วัดบนเครื่องจริง

รายละเอียดระบบและข้อจำกัด: [docs/GAME-DESIGN-TH.md](docs/GAME-DESIGN-TH.md) · หลักฐานตรวจ: [docs/VALIDATION.md](docs/VALIDATION.md)

## ทรัพย์สิน

ฉากหลักใช้ **Phaser + WebGL** และกริด **isometric 2:1**; พื้น ผนัง เฟอร์นิเจอร์ และบ้านรอบกิลด์วาดสำหรับมุมเฉียงเดียวกัน จัดลำดับการบังตามตำแหน่งบนพื้น และแปลงการแตะ/วางของกลับเป็นพิกัดกริด; Canvas 2D ใช้เตรียมเท็กซ์เจอร์พิกเซลและภาพเล็กในเมนู งานสไปรต์และสภาพแวดล้อมสร้างสำหรับโครงการนี้ ฟอนต์ Noto Sans Thai ใช้ SIL Open Font License ดู [assets/fonts/OFL.txt](assets/fonts/OFL.txt) และ metadata ในฟอนต์

[Dungeon Village 2 — Kairosoft](https://kairosoft.net/game/appli/bouken2.html) เป็นเรฟมุมเฉียงแบบ isometric และแรงบันดาลใจเรื่องการเติบโตของสถานที่และนักผจญภัย ไม่มีการนำทรัพย์สินเกมนั้นมาใช้

[Pixel Art Top Down — Village โดย Cainos](https://cainos.itch.io/pixel-art-top-down-village) เป็นเรฟวัสดุและภาษาภาพ ไม่ได้รวมทรัพย์สินของ Cainos ในเกม Phaser ใช้ MIT License ซึ่งแนบอยู่ใน build และไฟล์เดี่ยว
